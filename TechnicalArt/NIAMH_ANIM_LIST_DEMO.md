当前采用两个用户手绘修订姿势，不再制作第三个动作。按事件规模和用途选姿势，不将两个动作视为三个高度阶段中尚缺一张。

## 1. Demo 动作需求与状态

以下是完整 Demo 的需求草案；**目前只实现了前五项的六部件试玩版本**。时长是设计起点，最终要按真实控制器和 Play Mode 画面调整。

### 已有试玩版本

1. **待机 idle**：全程和对话时使用。设计循环约 1.6–2 秒，以呼吸及轻微头发、披风响应为主；v8 的披风仍与身体相连。
2. **走 walk**：全程使用，约 0.8 秒一轮；原计划四个关键姿势。
3. **跑 run**：森林助跑和跑跳大沟使用，约 0.5 秒一轮；应有前倾及发丝、披风后飘。Unity 已有 Run 状态，但 5.6u/s 实际跑速尚未单独留证。
4. **跳 jump**：S1 石墙、森林两条沟，以及将来的 S3 浮石和高台。按起跳、上升、最高点、下落衔接；v8 由控制器的实际落地状态和纵向速度驱动，不照搬离线 2 秒循环。
5. **落地 land**：所有落地使用。目标是脚保持接地、上身轻微下沉并恢复；实际衔接以 Unity 试玩为准。

### 后续按场景制作

6. **伸手互动 reach**：单次并可保持，设计约 0.4 秒；用于推栅门、查看三螺旋石和涂鸦、放石牌。需要张开的手型；先在现有栅门交互中试姿势。
7. **蹲下拾取 crouch_pickup**：单次约 0.6 秒；用于捡铁十字、发卡和石牌，也可停在蹲姿查看脚印。
8. **十字架双动作**：按本文最新原则选择胸前局部使用或举起剧情释放。旧 0.8 秒仅是早期设计起点；大光线和大型障碍湮灭的剧情时序尚未确定。当前两张用户静帧已整理，动画和发光层另做。
9. **受击 hurt**：单次约 0.3 秒；S3 深坑或受控荆棘，配合存在值褪色 Shader。
10. **回头受惊 startle**：S3 入口关闭时约 0.5 秒；可在待机之上叠加头和上身姿势。

褪色（存在值降低）用 Shader，不做动作。朝左一律 `flipX`。

## 3. 表情（Sprite Resolver 切换，不算动作）

眼睛：睁 / 闭（眨眼）/ 惊讶；嘴：闭 / 张。S4 名字交易时的犹豫可用「眼睛半闭 + 低头」叠加。

## 4. 对拆件的影响

- 手型只需三种：张开、握拳、举十字架。
- 必须有独立的 `cross` 部件（断绳 / 系好两态）和发光层；挎包、手绳保持独立。
- 因为删掉了攀爬，不需要手臂高举过头顶的完整权重；肩部重叠区按 `NIAMH_RIG_PARTS.md` 的 10–15 px 即可。
- 估算：10 个片段（其中 startle 为叠加姿势），比技术美术方案原表少 4 个。
