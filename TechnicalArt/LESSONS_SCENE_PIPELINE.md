# 经验库：2D 横版场景从出图到 Unity（《妖精丘陵》第一章，2026-10-26 ~ 10-30）

> 留作以后做 S2–S4、其他章节或其他项目时查阅。每条都来自实际踩过的坑。按「出图 → 拆层 → 物件 → 进 Unity → 试玩」排列。

## 1. 出图（Midjourney / Nano Banana）

- **先定比例再出图**：用角色侧面静态图定单位（本项目 1u = 100 px，妮芙 2.1u），所有场景按这个尺度检查。原尺度能放下就不要放大关键帧，放大会把天空和屋顶裁出镜头。
- **横版提示词要强调「侧视、地面水平贯穿」**，并在 `--no` 里排除 `perspective road, vanishing point`；否则 MJ 会画成往远处延伸的透视小路。
- **风格参考用已经定下的场景图**（菜单背景、上一个场景的关键帧），`--sw 40` 左右；`--sw` 太高会把参考图的冷暖色一起带进来。
- **MJ 编辑器扩图**（不用上传）可以一次扩到 3.5:1 左右；编辑器里 `--sw` 会被忽略，`--ar` 要删掉，比例由画布决定。偶尔提交失败（fail to upload），重试即可。
- **物件单独出图**：纯色浅米底、`strict side view, flat 2D side elevation`。方块类物件（草捆）MJ 很难完全去掉透视，露一点顶面可以接受；高而窄的东西（高墙）容易画成柱子或塔，直接用同一张矮墙放大更统一。
- **在原图上局部修改用 Nano Banana（Google AI Studio，Nano Banana 2.1）**：例如把方洞改成自然的土沟，它会保留周围画面和画风。同一个对话里连续做同类修改，画法会一致。MJ 适合出整张关键帧和单独物件，不适合精确的局部修改。
- 「剖面」「坑」这类概念 MJ 会画成一整个小场景，不要用它出。

## 2. 拆层

- **被遮挡、视差时会露出的区域，只能用真实画面补**：原图的另一部分，或 MJ 编辑器擦除重画（例如 S1 村舍背后的 `_pan_empty`）。拉伸、平均色、插值、镜像，一动就穿帮。
- **前景物体又大又密时不要硬拆**：森林前排粗树干背后补不出来，最后把路面以上整张原图作为一个背景层（视差 0.4），只靠「背景 / 路面 / 前景」三层的速度差做纵深，画面反而干净。
- 按颜色分天空容易把受光的山顶分进天空，出现两条山脊线；改为逐列找山脊位置。低饱和的山坡（灰绿、蓝绿）也要算进山体色。
- 原画里的墨线（树线下、山肩上）要整条留在同一层，否则视差一错开就变成碎点或黑块。
- **预览以 MP4 为准**：GIF 只有 256 色，会闪烁、变色，误判成画面问题。

## 3. 视差与眩晕（试玩后才发现）

- 移动快的层（前景 1.3）**不要有紧贴地面的细碎边缘**：碎草尖和不动的路面一错开就晃眼。去掉碎边、只留成片的形状。
- 前景太突出时：降低透明度（0.5 左右）+ 视差系数降到 1.1–1.15。前景遮挡本身是好的，能制造神秘感，只是不能抢眼。
- **背景和路面的交界是最容易晕的地方**：背景（慢）里的树根一路画到路边，路面（快）却不动。办法是在路面上沿加一条与路面同速的草土边，压住背景的底部，给眼睛一个稳定的参照。
- 以后出图时，背景层的地面部分尽量平淡、少细节，把有细节的东西（树根、石头）放在与路面同速的层上。

## 4. 物件与可读性

- **游戏物件要比写实比例夸张**：铁十字、荆棘丛、荆棘墙按「写实」比例放进去后，在 1080p 画面上几乎看不见。关键道具至少 1u 以上，阻挡物要明显高于最高跳（本项目最高跳 2.4u，荆棘墙做到 6u）。
- **关键道具用「先暗示、后揭示」**：远处只显示闪光星星，走近才显现，既引导玩家，又制造悬念。
- 门、门框这类物件要**拆成前后两部分**（左柱、门板在角色后面，右柱在前面），角色穿过时才有空间感；碰撞不要贴图片外框，用一道高隐形墙。
- 抠图：只把「与画布边缘连通的底色」当背景；被物体围住的底色（门下的空隙）要另外去掉；偏蓝的地面影子单独按颜色去。角色立绘里与底色接近的皮肤不能当背景删。
- 从一整排里截出的物件（荆棘墙中段）两侧是直的截口，脚本很难做出自然的边，交给 Nano Banana 修。

## 5. 进 Unity

- 所有层图片把**地面线放在图片底边上方固定像素**（本项目 270 px），Pivot 设成 `(0, 270/高度)`，放在原点就对齐。Unity 6 里自定义 Pivot 要通过 `TextureImporterSettings` 设置才生效（Codex v1 踩过）。
- Unity 自带 `JsonUtility` 读不了嵌套数组，布局 JSON 的地面折线要手动解析（Codex v1 踩过）。
- 粒子显示桃红色 = 没有材质或用了内置管线材质；URP 用 `Universal Render Pipeline/Particles/Unlit`。
- 工程里没有装 Cinemachine 时，一个只跟随 x 的小脚本就够用，不必为此装包。
- **每个场景都有的东西（主角、相机、HUD、游戏状态）放进一个常驻场景**，关卡场景 Additive 加载、只放关卡内容。改主角只改一处，跨场景数据不丢。单独打开关卡场景时自动补载常驻场景，方便调试和课堂演示。
- 交给另一台电脑的 Agent（Codex）时：一份「交接说明」（中文，给人也给 Agent）+ 一份「任务指令」（英文，`CommandForAgentToInitialRun/`），写清复制哪些文件、不复制哪些、完成后写进度文件和更新哪些总览、要在 Play Mode 验证什么。
- **手动调过的数值要写回数据**：用户在 Unity 里手调的碰撞，一旦用生成工具重建场景就会被覆盖。凡是手调的值都放进布局 JSON 的覆盖字段，由生成工具读取。
- **Nano Banana 出不了透明图**：先让它出纯白（或纯米色）底，再自己抠透明；带底色的版本也留着，需要实心底的地方直接用。
- 物件图片和碰撞不必一样大：散开的枝条、草叶只做视觉，碰撞只放实心部分，在布局里单独写 `collider_x` / `collider_w`。
- UI 文字压在亮色背景上：底下垫一块半透明黑块（Alpha 0.6），再叠金框和文字。
- **内容多的场景，速度差要分档**：森林背景（0.4）和路面（1.0）之间一步跳太大，交界带内容又多，就晕；中间加一层 0.65 的矮植被做过渡。开阔的田野（S1）没这个问题。
- 前景想要「镜头前的暗角」感，就把透明度渐变画进图里（上沿透明、往下变实变暗），比整体调 Alpha 自然。
- 跟着物件位置留的缺口（例如地沟处草土边留空）在视差下会显得很怪，宁可连续铺满。
- 「开 / 关」这类状态，用两张完整的图切换，比把一张图切开再藏一部分干净。
- 游戏进行中的提示文字用细框（细线 + 小角饰 + 半透明黑底）；分量重的装饰框只给菜单、对话框、背包。
- 发光效果用单独的遮罩层（Additive）只照亮缝隙和局部，不要整张染色；再配一盏 2D 点光源照亮周围。
- 关键物件的提示（星星）要有「触发点」，在玩家完成前一个挑战后才出现，引导更强。
- 开 / 关两张图里共有的部分（石柱）要用**同一份像素**：用 AI 补全的版本作为两种状态的底，关门图再叠回原图的门板，切换时才不会跳。
- 短音效（开门、拾取、湮灭）可以直接用程序合成，可调、可复现；AI 音乐工具适合整首 BGM，不适合几秒的音效。
- 循环 BGM 的接缝要在游戏引擎里听，或听「结尾 + 开头」拼接的测试文件；普通播放器循环时会自带停顿。
- **交给 Agent 的改动要分小批**：一次 10 条出了问题无法定位。按「会不会互相影响」分批（UI / 单场景画面 / 跨场景系统如加载器与音频），每批前 git commit，每批后用户手动走一遍。
- Agent 在副本工程里跑的自动测试，不能代替在用户实际打开的工程里按 Play；场景是否被重建（例如常驻场景漏改）也要在报告里写清。


## 2026-11-01 · 网络共享盘「能读不能写」
- 症状：Unity 工程在另一台电脑（Haoxi-RTX），本机通过映射盘 W: = `\\Haoxi-RTX\C` 访问；文件夹 NTFS 权限显示 Full Control，但新建文件仍提示 "Destination Folder Access Denied"。
- 原因：共享本身的权限（Share permission）是 `Everyone, READ`。网络访问要 **共享权限 和 NTFS 权限同时允许** 才能写，取两者中更严的那个。
- 排查：在共享所在电脑用**管理员**命令提示符运行 `net share C`（看 Permission）和 `net session`（看连进来的账户）。普通窗口会报错 5。
- 修复：`powershell -Command "Grant-SmbShareAccess -Name C -AccountName Administrator -AccessRight Change -Force"`，只给 Administrator 写，其他人保持只读。不要随手 `net use /delete`，删了要记得重新映射（`net use W: \\Haoxi-RTX\C /persistent:yes`）。
- 结果：Claude 可以把素材和布局 JSON 直接放进 Unity 工程（文件传输工具）；网络盘不挂到 Claude 的命令行，所以 git 和 C# 仍由 Codex 在本机做。

## 2026-11-01 · 布局数据：地面要覆盖到出口
- 森林布局 v4 把场景延长到 60u、出口放在 59.5，但最后一段地面仍停在 57.6，妮芙会在出口前掉下去。改长度 / 出口时，同步检查 `ground` 最后一段的终点和 `far` 宽度。可以在 `validate_layout.py` 里加一条：出口 x 必须落在某段地面上。

## 2026-11-01 · 分批交给 Codex 更稳
- 一次给 10 条改动 → 出错难定位、它会顺手改切场景逻辑。拆成 A（UI + 门）/ B（森林画面）/ C（音频），每批先 git commit、只准改列出的文件、不自测，用户逐批在 Play Mode 验收。A 基本一次通过（只补了门柱前后层）；B 画面问题较多（见下两条），但改动面小，好定位。
- Claude 先把素材和数据放进工程，指令只剩「导入设置 + 少量脚本 + 重建保存」，Codex 改动面越小越不容易出错。

## 2026-11-01 · URP 2D：加一盏灯，整个场景就进入“光照模式”
- 症状：Batch B 给荆棘墙加了一盏红色 Point Light 2D 后，进森林时画面一开始是黑的。
- 原因：`Sprite-Lit-Default` 的 Sprite 只显示被 2D 灯照到的部分；没有全局光照着时就是黑的。加灯前看不出这个问题。
- 做法：全局光只放一盏在 Core，每关通过 `LevelInfo` 设环境色 / 强度，并在淡入前写入；关卡场景里不放 Global Light。想要“暗场”气氛时，故意压低环境光，再用角色随身光和辅助灯照亮（森林方案见 v3_fix B2）。远景天空用 `Sprite-Unlit-Default`，保持亮度。

## 2026-11-01 · 粒子材质挂在 SpriteRenderer 上，颜色会丢
- 症状：荆棘墙红光遮罩（白色软光斑）显示成一大片灰白、糊糊的纹理，像被拉伸、像素不清。素材本身没问题。
- 原因：遮罩用 URP `Particles/Unlit`（Additive）挂在 SpriteRenderer 上，代码用 `SpriteRenderer.color` 染色和做呼吸；粒子 Shader 不读这个颜色，材质 `_BaseColor` 又是白色 → 白色满强度叠加。
- 做法：这类 Additive 叠加层用 `MaterialPropertyBlock` 写 `_BaseColor`；材质默认颜色就设成目标色，编辑器里不运行也能看出对错。验收时先在 Scene 视图看一眼颜色。

## 2026-11-01 · 前后遮挡：只把“该挡人”的部分单独提一层
- 栅门整张放在妮芙后面时，站在柱子位置看不出前后关系；但两根柱子都提到前面又不对（用户只要右柱在前）。
- 做法：不拆原图（拆过会留木条），另做一张**同画布、只保留要挡人的部分**的图，放在角色前面一层，和原图叠在同一位置。开关门只换后层，前层不动。

## 2026-11-04 · 粒子速度曲线三轴要同一模式
- 症状：按 Q 看不到烟雾，Console 每帧报 `Particle Velocity curves must all be in the same mode`（几百条）。
- 原因：脚本只给 Velocity over Lifetime 的 y 设了随机范围（Two Constants），x、z 保持默认常数。
- 做法：脚本里设速度时 x / y / z 一起设，模式相同（不用的轴写 `MinMaxCurve(0,0)`）。Noise、Force over Lifetime 同理。

## 2026-11-04 · Global Light 放在角色下面 ≠ 角色身上的灯
- Global Light 2D 不管挂在哪都照亮整个画面。想要“只照亮角色周围”必须用 Point Light。暗场关卡先出一张合成预览（`tools/mock_forest_dark.py`）让用户定亮度，再写给 Codex。

## 2026-11-05 · 暗场里的特效要“自带光”
- 森林压暗后，原来的暗紫烟雾和淡出完全看不见。暗场特效要么用 Additive（自己发光），要么配一盏临时点光源（爆闪）把周围照亮；暗色烟只当底。
- 放在角色前面的物件，底边和角色脚在同一条线上会显得“悬空”。在物件脚下加碎石 / 草丛，底边比地面线略低，前后关系就对了。

## 2026-11-05 · 暗场会暴露抠图白边；点光会打出光斑
- 亮场里看不出的浅色抠图边（半透明像素颜色偏白），压暗后变成一圈白线。暗场关卡的物件要先做“去白边”：边缘颜色用内部颜色外扩填充（`tools/fix_thornwall_edge.py`）。
- 小装饰光（收集物光点）不要用 Point Light：它会照亮背后的植被形成光斑。用 Additive 小 Sprite 自发光即可。

## 2026-11-05 · 旋转的特效图 pivot 要在中心
- 星星旋转时“甩”出去，是因为特效图按物件规则导入成左下角 pivot。会旋转 / 缩放的特效图（星星、光晕）导入时 pivot 一律 (0.5, 0.5)。
- “排在最前面”要同时改 SpriteRenderer 和 ParticleSystemRenderer 的 Sorting Order，只改一个仍会被挡。
